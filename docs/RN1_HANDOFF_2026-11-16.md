Tester **M0 = market maker / YES+NO / inventaire / rebates sans oracle**, **M1 = moteur d'edge utilisant des probabilités externes**, **M2 = market maker hybride avec fair value et contrôle de risque**. Le document canonique est **`docs/RN1_BLACKBOX_SYSTEM_IDENTIFICATION_ORACLE_VS_MAKER_2026-11-16.md`** (commis sur main). Un *oracle de probabilité externe* n'est pas l'oracle de règlement de Polymarket.

**Contrôle d'existence des sources** : archive historique figée 756k fills ; `rn1_independent_price_jobs` complete (29 731 Maker BUY et 3 506 Taker BUY dans l'échantillon de markouts) mais **prix Polymarket historiques ≠ probabilités externes** ; au contrôle live **437 sondes complètes**, **6 140 livres valides**, **247 marchés / 76 événements**, **493 fills Maker inferred**, **408** avec prochain livre du même token ≤2 minutes après fill ; aucune table RN1 inspectée dédiée à un historique indépendant d'odds bookmakers. Captation 1/min trop peu dense pour identifier un ordre Maker originel. Pour discriminer M1 de M0, le test le plus puissant est un choc d'odds externe *avant* un mouvement Polymarket, avec les décisions de RN1 conditionnelles à inventaire/spread/phase ; sans odds vraiment horodatées, **M1 non testable, pas réfuté**.

**Premier test M0 vs soupçon d'oracle (diagnostic, non-concluant)** : `docs/RN1_ORACLE_VS_MAKER_FIRST_MARKOUT_DECOMPOSITION_2026-11-16.md`. Sur **374 fills Maker inférés**, **72 marchés/42 événements**, pré-book âgé ≤60s et premier book post-fill ≤2min : markout brut vs fill **+0.00642 USDC/share**, décomposé en **+0.00472 USDC/share** d'écart au midpoint préfill et **+0.00170 USDC/share** de variation du midpoint ; médiane de variation du midpoint = 0 ; seulement 41,18 % des fills suivis d'un midpoint supérieur. Moyenne à poids égal par événement du changement de midpoint **+0.00969**, intervalle normal approximatif **±0.01355**, inclut zéro. **Ne pas appeler l'écart préfill un vrai spread capturé**, car le livre peut dater de 60s. ## Changement de méthode prioritaire — 16 novembre 2026

La règle fixe 1 % **par fill** est peu compatible ; **par ordre** non tranché, car les ordres Maker peuvent être fragmentés. L'onglet cible est **RN1 · Modèles** avec un classement des hypothèses et non une autre accumulation de tableaux descriptifs.
